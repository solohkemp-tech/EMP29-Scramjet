# EMP29 Pro 2.1 · Scramjet

نسخه توسعه‌یافته Scramjet با محیط فارسی/انگلیسی و پشتیبانی راست‌به‌چپ/چپ‌به‌راست، برند **EMP29**، لوگو و تصویر اختصاصی، و پیوند [تلگرام @emp29](https://t.me/emp29).

این بسته شامل برنامه قابل اجرا، فایل‌های ساخته‌شده و سورس کامل پروژه اصلی و تغییرهای EMP29 است. هسته JavaScript، کنترلر، ابزارها و بازنویس WASM از سورس commit زیر ساخته شده‌اند؛ بسته قدیمی npm جایگزین سورس فعلی نشده است:

`b14b709ac190b786dd03becbd0728ab72bdd3ad6`

اصلاحات EMP29 در JavaScript با شناسه `emp29-core-2.1.0` ثبت شده‌اند: حذف کامپایل تکراری ماژول WASM، دریافت مشترک باینری کنترلر و Worker، اعتبارسنجی پاسخ با امکان تلاش دوباره، تبدیل باینری در قطعات محدود و اصلاح آماده‌بودن کنترلر. در مقایسه محلی ۲۵ بازنویسی با نسخه 2.0، تعداد کامپایل از ۲۵ به ۱ رسید و خروجی‌ها یکسان بودند. این نتیجه ضریب سرعت مرور، شبکه یا ویدئو نیست. جزئیات در [VALIDATION.md](../VALIDATION.md) است.

[English guide](../README.en.md) · پروژه اصلی: [MercuryWorkshop / Scramjet](https://github.com/MercuryWorkshop/scramjet). راهنمای اصلی در [UPSTREAM_README.md](../UPSTREAM_README.md) نگه داشته شده است.

## اجرای سریع روی کامپیوتر

Node.js 24 LTS نصب کن؛ حداقل نسخه قابل استفاده 22.16 است. سپس ZIP را استخراج کن و داخل پوشه `EMP29_Scramjet/emp29` اجرا کن:

```sh
npm ci --omit=dev --ignore-scripts
npm run doctor
npm start
```

نشانی برنامه: **http://localhost:3030**. اجرای محلی به Rust، pnpm یا ساخت دوباره WASM نیاز ندارد. مرورگرهای به‌روز Chrome، Edge یا Firefox پیشنهاد می‌شوند. نصب وابستگی‌های npm به اینترنت نیاز دارد.

در ویندوز می‌توانی `Run_EMP29.bat` را اجرا کنی؛ در Linux/macOS دستور `bash run.sh` از پوشه اصلی همین کار را انجام می‌دهد. سرور با Ctrl+C متوقف می‌شود. اسکریپت ویندوز در این محیط آزمایش نشده است.

برای محافظت با رمز، پیش از `npm start` دستور زیر را اجرا کن:

```sh
npm run setup
```

برای اجرای محلی، پرسش دامنه را خالی بگذار؛ پورت پیش‌فرض 3030 است. رمز حداقل ۱۲ کاراکتر دارد، هنگام ورود نمایش داده نمی‌شود و فقط هش scrypt آن در `.env` ذخیره می‌شود. فایل `.env` و نسخه پشتیبانش را منتشر نکن.

## قابلیت‌ها

- انتخاب فارسی/English در سربرگ، صفحه ورود و تنظیمات؛ تغییر زنده زبان، جهت صفحه، پیام‌ها، تاریخ و اعداد بدون بارگذاری دوباره تب‌ها. ترجیح زبان در پشتیبان ذخیره می‌شود و عنوان‌ها و یادداشت‌های کاربر به زبان خودشان می‌مانند.
- رابط RTL/LTR با فونت محلی Vazirmatn، تم تیره/روشن/سیستم، سه رنگ تأکید و حالت حرکت کمتر؛ چیدمان سازگار با صفحه کوچک.
- حداکثر ۲۴ تب در ۸ فضای کاری با نام و رنگ دلخواه؛ انتقال تب بین فضاها، جست‌وجوی همه تب‌ها در فرمان‌ها و کپی پیوندهای یک فضا.
- ذخیره ۱۲ نشست نام‌دار و بازیابی بدون تکرار نشانی؛ تب‌های بازیابی‌شده تا انتخاب‌شدن بارگذاری نمی‌شوند. فضاهای کاری از کوکی مشترک استفاده می‌کنند و حساب جدا نمی‌سازند.
- نمای دوگانه دو تب یک فضا؛ روی صفحه کوچک، دو پنل زیر هم قرار می‌گیرند. تب‌های نمای دوگانه از خواب زمان‌بندی‌شده حفظ می‌شوند.
- مطالعه مقاله با Mozilla Readability، کتابخانه ۱۵ مطلب، یادداشت، جست‌وجو و خروجی Markdown؛ موتور مطالعه فقط هنگام استفاده دریافت می‌شود و خروجی آن متن ساده است.
- سنجاق تب، بازگرداندن تب بسته، بزرگ‌نمایی و سقف تب زنده قابل انتخاب ۲/۴/۶/۱۰. برای بازکردن تب تازه، تب‌های قدیمیِ غیرفعال آزاد می‌شوند؛ تب سنجاق‌شده، در حال بارگذاری، نمایان یا دارای پخش شناسایی‌شده حفظ می‌شود. کاهش سقف با پذیرش تب زنده بعدی اعمال می‌شود؛ اگر تب قابل آزادکردن کافی نباشد، پیام راهنما نمایش داده می‌شود.
- نشانک با عنوان دلخواه، جست‌وجو و حذف؛ تاریخچه قابل جست‌وجو و پاک‌سازی؛ ورود و خروج نسخه پشتیبان JSON.
- جست‌وجو با Google، DuckDuckGo، Bing یا Brave؛ میان‌برهای شروع و فرمان‌های قابل جست‌وجو.
- انتخاب خودکار Libcurl/Epoxy در راه‌اندازی، انتظار قابل تنظیم برای آماده‌شدن WASM و یادآوری موتور موفق در همان نشست مرورگر؛ حالت دستی هر دو موتور هم موجود است.
- سرور Wisp اصلی و دو مسیر جایگزین، بررسی واقعی پیام آغاز پروتکل و انتخاب مسیر سالم پیش از راه‌اندازی موتور؛ زمان handshake سنجیده می‌شود و معیار پهنای باند نیست.
- تغییر دستی موتور آماده برای درخواست‌های بعدی از بخش کنترل سایت؛ شکست تغییر، موتور قبلی را نگه می‌دارد. درخواست سایت، ارسال فرم یا پرداخت خودکار تکرار نمی‌شود.
- سه تنظیم سریع «متعادل»، «سبک» و «ویدئو». حالت ویدئو خواب خودکار و کش اضافی را خاموش می‌کند؛ افزایش سرعت شبکه یا پشتیبانی از DRM را تضمین نمی‌کند.
- مسدودسازی اختیاری دامنه‌های ردیاب و قوانین شخصی، استثنای هر سایت و شمارنده پاسخ‌ها/مسدودسازی/کش؛ محدوده آن مسدودسازی دامنه است و ضدتبلیغ یا ضداثر انگشت کامل نیست.
- کش محدود فایل‌های کوچک و عمومی، بدون کش HTML، API، داده خصوصی یا استریم ویدئو/صدا؛ حذف کش و کوکی سایت‌ها از تنظیمات.
- تعمیر سرویس مرورگر، پیام خطای دوزبانه و انتظار واقعی برای آماده‌شدن WASM پیش از درخواست سایت.
- نصب میان‌بر PWA، آیکن مناسب نصب، لوگو و تصویر اختصاصی بهینه‌شده EMP29، لینک تلگرام و دریافت سورس از داخل برنامه. PWA مرور آفلاین وب را فراهم نمی‌کند.
- سرور Wisp همراه برنامه، رمز ورود اختیاری، نشست ۱۲ ساعته، محدودیت تلاش ورود و اتصال و حداکثر ۴ بررسی رمز هم‌زمان، محافظت Origin، هدرهای محافظتی و فیلتر مقصدهای خصوصی شبکه.

تنظیم‌ها، نشانک‌ها، تاریخچه، فضاها، نشست‌ها و مطالب در مرورگر همان دستگاه ذخیره می‌شوند و بین دستگاه‌ها همگام نمی‌شوند. پشتیبان شامل تنظیمات، نشانک‌ها، فضاها، نشست‌های نام‌دار و متن/یادداشت ذخیره‌شده است؛ رمز ورود و کوکی سایت‌ها در آن نیست. مطالب ذخیره‌شده ممکن است شخصی باشند؛ پشتیبان را نزد خودت نگه دار. بسته خام بدون `.env` فقط روی loopback محلی گوش می‌دهد.

مقایسه با نسخه پایه و EMP29 1.0 در [COMPARISON.md](../COMPARISON.md)، منابع طراحی امکانات در [RESEARCH.md](../RESEARCH.md) و روش ارتقا در [RELEASE.md](../RELEASE.md) آمده‌اند.

## نصب روی سرور با دامنه HTTPS

Service Worker روی دامنه یا IP راه دور با HTTP فعال نمی‌شود. برای انتشار، یک دامنه با HTTPS معتبر استفاده کن و EMP29 را در ریشه دامنه (`/`) قرار بده؛ نصب زیر مسیر `/proxy/` پشتیبانی نمی‌شود.

بسته را در `/opt/emp29` استخراج کن، به شکلی که فایل `/opt/emp29/emp29/server.mjs` وجود داشته باشد. سپس:

```sh
cd /opt/emp29/emp29
npm ci --omit=dev --ignore-scripts
npm run setup
npm run doctor
```

در setup نشانی واقعی مثل `https://browser.example.com` را وارد کن، پورت را 3030 بگذار و رمز انتخاب کن. دامنه بدون مسیر وارد می‌شود. تنظیم پیش‌فرض، سرویس داخلی را روی `127.0.0.1:3030` نگه می‌دارد و `TRUST_PROXY=true` را برای HTTPS تنظیم می‌کند.

برای سرویس systemd با Node.js سراسری نصب‌شده:

```sh
sudo bash deploy/install-systemd.sh
sudo journalctl -u emp29 -n 50 --no-pager
```

این اسکریپت کاربر سرویس `emp29` ایجاد می‌کند، مالکیت پوشه برنامه را به آن می‌دهد و سرویس را فعال می‌کند. نصب در `/root` یا `/home` به‌دلیل محدودیت سرویس پذیرفته نمی‌شود. نمونه واحد در `deploy/emp29.service` است؛ فایل سرویس قبلی هنگام جایگزینی پشتیبان گرفته می‌شود.

برای reverse proxy یکی از نمونه‌ها را با دامنه واقعی خودت تنظیم کن:

- `deploy/Caddyfile.example`: Caddy گواهی HTTPS و ارتقای WebSocket را مدیریت می‌کند. DNS دامنه باید به سرور برسد و پورت‌های 80/443 در دسترس باشند.
- `deploy/nginx.conf.example`: فقط location نمونه را به server block دارای HTTPS همان دامنه اضافه کن. فایل تنظیمات کامل سایت‌های فعلی را جایگزین نکن. هدرهای Host، X-Forwarded-Proto و Upgrade باید منتقل شوند.

پس از ویرایش، پیکربندی reverse proxy را با ابزار خودش بررسی و reload کن. مقدار `EMP29_ORIGIN` باید دقیقاً دامنه HTTPS برنامه باشد. پورت 3030 را عمومی نکن. برای تغییر پورت، هم `.env` و هم مقصد reverse proxy را عوض کن. بعد از تغییر `.env`، سرویس را restart کن:

```sh
sudo systemctl restart emp29
```

راهنما و تنظیمات سرور در بسته آماده‌اند؛ این نسخه روی سرور شخصی تو نصب یا جایگزین نشده است.

## Docker، اختیاری

ابتدا در پوشه `emp29` فایل `.env` را با `npm run setup` بساز. سپس:

```sh
docker compose up -d --build
```

کانتینر با کاربر غیرریشه و فایل‌سیستم فقط‌خواندنی اجرا می‌شود؛ پورت میزبان فقط `127.0.0.1:3030` است و همچنان برای دسترسی راه دور reverse proxy HTTPS لازم است. Docker در محیط ساخت این بسته اجرا نشده است.

## عیب‌یابی اتصال و WASM

1. ابتدا از بخش «اتصال» بررسی اتصال و گزارش را اجرا کن. عدد زمان پاسخ، رفت‌وبرگشت سرور است؛ تست سرعت دانلود یا ویدئو نیست.
2. روی دامنه واقعی، HTTPS و مسیر WebSocket `/wisp/` را بررسی کن. خطای HTTP 426 روی `/wisp/` در درخواست معمولی HTTP طبیعی است؛ این مسیر WebSocket است.
3. برای خطاهای کش یا نصب قبلی، «تعمیر اتصال» را بزن. فقط Service Worker این برنامه و کش‌های EMP29/Scramjet پاک می‌شوند. نشانک‌ها و تنظیم‌ها باقی می‌مانند. اگر قبلاً پراکسی دیگری روی همان دامنه نصب بوده، استفاده از زیردامنه تازه ساده‌تر است.
4. حالت «خودکار» در راه‌اندازی، پس از شکست آماده‌سازی Libcurl، Epoxy را امتحان می‌کند. کاربر نسخه قبلی می‌تواند این حالت را در تنظیمات انتخاب کند. از «کنترل سایت» هم می‌توان موتور دیگر را آماده کرد؛ تغییر انتخاب ذخیره‌شده در تنظیمات، صفحه را دوباره بارگذاری می‌کند.
5. خطای 401 یعنی نشست ورود منقضی شده؛ دوباره وارد شو. خطای 429 یعنی سقف تلاش یا اتصال رسیده است.

فایل‌های WASM با MIME صحیح و مسیر دارای هش محتوا سرو می‌شوند. مسیر گم‌شده موتور به‌جای WASM، HTML دریافت نمی‌کند. ثبت Worker به‌تنهایی «آماده» محسوب نمی‌شود و برنامه تا کنترل واقعی صفحه و آماده‌شدن موتور TLS صبر می‌کند. این تغییرها علت‌های رایج خطای «Libcurl WASM not initialized» را پوشش می‌دهند؛ رفتار نهایی روی مرورگر و سرور واقعی باید بررسی شود.

Wisp داخلی فقط مقصدهای عمومی با نام دامنه روی پورت‌های 80/443 را قبول می‌کند؛ IP مستقیم، شبکه محلی و UDP مسدودند. در نتیجه WebRTC/UDP یا سرویس‌های دارای پورت خاص ممکن است کار نکنند. مقصدها از مسیر سرور EMP29 دریافت می‌شوند؛ کیفیت و محدودیت شبکه سرور بر نتیجه اثر دارد. Scramjet هسته‌ای آزمایشی است؛ ورود همه سایت‌ها، DRM، تماس تصویری و پخش همه ویدئوها تضمین نمی‌شود.

## توسعه و ساخت

دستورها را در **پوشه `emp29`** اجرا کن؛ `npm install` در ریشه monorepo لازم نیست:

```sh
npm ci
npm run build
npm test
npm run check
python3 scripts/package-release.py --output /path/to/EMP29_Scramjet_v2.0.0.zip
npm run doctor
```

`npm run build` رابط، هسته و کنترلر را از سورس موجود و WASM همراه بسته می‌سازد؛ سپس مسیرهای دارای هش و فایل‌های Brotli/Gzip تولید می‌کند. بعد از build برای ساخت دوباره `dist/source.zip` دستور بسته‌بندی را اجرا کن. build به‌تنهایی این ZIP را تولید نمی‌کند.

تصاویر اصلی در `brand/` هستند. برای بازسازی اندازه‌های وب و آیکن نصب، `npm run brand` را پیش از build اجرا کن. Readability در یک بخش JavaScript جداگانه ساخته می‌شود. آزمون DOM، ماژول‌های ساخته‌شده و بخش‌های مشترک را با VM Modules اجرا می‌کند؛ این گزینه فقط برای آزمون است و اجرای سرور به آن نیاز ندارد.

برای تغییر سورس Rust، ابتدا Rustup با nightly مشخص‌شده و `wasm-bindgen-cli 0.2.105` را نصب کن، سپس `bash scripts/rebuild-rewriter.sh` و `npm run build` را اجرا کن. جزئیات سازنده WASM در `vendor/provenance.json` آمده است. بسته پیش‌ساخته برای کاربر معمولی به این ابزارها نیاز ندارد.

گزارش بررسی در [VALIDATION.md](../VALIDATION.md) و تغییرها در [CHANGELOG.md](../CHANGELOG.md) است. آزمون‌های خودکار DOM و شبکه محلی انجام شده‌اند؛ بازبینی تصویری با مرورگر واقعی و تست سایت‌ها/ویدئو روی سرور مقصد انجام نشده است.
